# 学术个人主页 · 单文件版

一个**零依赖、零构建、单文件**的学术个人主页模板。双击 `index.html` 即可打开,也可以直接托管到 GitHub Pages。内置一个可视化后台管理界面,不懂代码也能改内容。

> 演示数据均为虚构,请在发布前替换为你自己的真实信息。

## 快速开始

**方式一:直接打开**

下载仓库,双击 `index.html`。浏览器里就能看到完整效果。

**方式二:本地起个服务(推荐)**

部分浏览器对 `file://` 协议下的 `content.json` 读取有限制(读不到会静默回落到内置默认内容,不影响使用)。想验证「读仓库文件」这条路径,起个静态服务:

```bash
# Python(系统自带)
python -m http.server 8000

# 或 Node
npx serve .
```

然后访问 <http://localhost:8000>。

## 目录结构

```
.
├── index.html          主页面(单文件,含全部样式与脚本)
├── admin.html          后台管理界面(单文件,独立可用)
├── content.json        站点内容(可选;改了它首页就会跟着变)
├── site-content.js     同上的 JS 版本(可选;方便直接改代码的人)
├── CNAME.sample        自定义域名示例(要用时重命名为 CNAME)
├── .nojekyll           告诉 GitHub Pages 跳过 Jekyll 处理
├── .gitignore          Git 忽略规则
├── LICENSE             MIT 许可
└── README.md           本文件
```

**最小可用集合只有 `index.html` 一个文件。** 其余的都是可选的:删掉 `content.json` / `site-content.js` 首页仍能正常运行,只是内容回落到内嵌的出厂默认;删掉 `admin.html` 也不影响站点。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库,比如 `my-homepage`。

2. 把本目录的文件推上去:

   ```bash
   git init
   git add .
   git commit -m "初始化个人主页"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/my-homepage.git
   git push -u origin main
   ```

3. 打开仓库的 **Settings → Pages**。

4. **Source** 选 `Deploy from a branch`,**Branch** 选 `main` / `(root)`,保存。

5. 等一两分钟,访问:

   ```
   https://<你的用户名>.github.io/my-homepage/
   ```

### 想要 `https://<你的用户名>.github.io` 这种根地址?

把仓库命名为 `<你的用户名>.github.io`(例如 `chenmingyuan.github.io`),不用改任何配置,Pages 会自动部署到根路径。

### 想要自己的域名?

1. 把 `CNAME.sample` 重命名为 `CNAME`,内容改成你的域名(只写域名,不带 `https://`)。
2. 提交推送。
3. 在域名服务商处按 `CNAME.sample` 里的说明添加 A 记录或 CNAME 记录。

### 关于 `.nojekyll`

GitHub Pages 默认用 Jekyll 处理站点。Jekyll 会**忽略以下划线开头的文件**。本仓库目前没有这类文件,但保留 `.nojekyll` 可以:
- 跳过 Jekyll 构建,部署更快
- 避免将来添加 `_` 开头的资源时被静默丢弃

这个文件是**空文件**,内容为空是正确的 —— 它的存在本身就是信号。

## 后台管理界面

访问 `admin.html`(主页右上角的齿轮图标也可以进入)。

- **默认口令:`admin`**
- 登录后可在「设置」里改成自己的口令,留空则**取消口令保护**

> **安全提示:** 口令仅保存在浏览器 `localStorage` 中,用于防止他人误改,**不是真实的安全机制**。任何人都能通过开发者工具查看或绕过。因此:
> - 不要在公开站点上存放敏感信息
> - 如果内容确实需要保护,应换成服务端鉴权

### 功能一览

| 分区 | 说明 |
|---|---|
| **仪表盘** | 内容量概览、数据来源与优先级说明、一键保存/导出/导入 |
| **个人信息** | 姓名、职称、单位、自我介绍、横幅文案、页脚署名、头像上传 |
| **首页统计** | 首页那排关键数字(增删改、调序) |
| **个人简介** | 简介段落、学术兼职、研究标签 |
| **研究方向** | 研究卡片(标题/描述/关键词标签) |
| **博客文章** | 文章列表(日期/标题/摘要/分类/阅读时长/链接),支持按日期排序 |
| **工作经历** | 时间线与荣誉奖项 |
| **教学与招生** | 授课课程、招生说明与要求 |
| **联系方式** | 联系条目(图标/名称/内容/链接) |
| **主题默认值** | 访客首次打开时的模式、色相、透明度、鼠标特效 |
| **实时预览** | 内嵌 iframe 预览首页,保存后点刷新即可看到最新效果 |
| **JSON 源码** | 直接编辑完整 JSON,带语法校验 |
| **设置** | 改口令、导出/导入、重置主题、清除本机编辑 |

### 便利功能

- **撤销 / 重做** —— 顶栏按钮或 `Ctrl+Z` / `Ctrl+Y`
- **快捷键保存** —— `Ctrl+S`
- **离开提醒** —— 有未保存改动时关闭页面会提示
- **实时同步** —— 后台保存后,已打开的主页标签页会自动刷新
- **头像自动压缩** —— 上传的图片在浏览器内等比缩放到最长边 480px 并压为 JPEG,base64 内嵌,不依赖图床

## 三种改内容的方式

按「优先级从低到高」排列,后写入的覆盖先前的:

```
① 出厂默认(内嵌在 index.html 里)
        ↓ 被覆盖
② 浏览器本地编辑(后台改的,存在 localStorage)
        ↓ 被覆盖
③ content.json(仓库里的文件)
```

### 方式一:用后台改(推荐给不写代码的人)

进 `admin.html` → 改 → 点「保存并应用」→ 回主页刷新即可。

改动存在**本机浏览器**,不会同步给别人。

### 方式二:改仓库文件(推荐给要公开发布的人)

1. 在后台改好后,点「**导出 content.json**」下载文件
2. 用它替换仓库里的 `content.json`
3. 提交推送

这样所有访客看到的都是新内容。

### 方式三:直接改代码(推荐给开发者)

1. 改 `site-content.js`(JS 格式,能写注释)或 `content.json`(纯 JSON)
2. 或者直接改 `index.html` 里 `defaultContent()` 函数返回的对象

> **注意:** `site-content.js` 目前**不参与**站点运行,它只是一份「可以直接照抄的模板」。要让它生效,请把内容同步进 `content.json`,或改 `index.html` 内置的默认值。

### 关于字段留空

- 留 `undefined`(不写这个键)→ **保留**上一层的值
- 显式写 `null` → **清空**
- 数组 → **整体替换**(不是逐项合并),所以删掉一条博客后旧数据不会「复活」

### 富文本说明

`bio`、`desc`、`paragraphs` 等字段支持**极少数** HTML 标签:

| 标签 | 效果 |
|---|---|
| `<strong>文字</strong>` | 加粗(用在正文里通常显示为主题强调色) |
| `<br>` | 强制换行 |

**其他标签一律不要写。** 这些字段的内容是通过 `innerHTML` 注入的,写 `<script>` 之类的标签会被浏览器执行。内容来源可信时没问题,但**不要把这些字段开放给不受信任的输入**。

### 图标可选值

`contact.items[].icon` 支持以下 6 个键,对应内置 SVG 图标:

| 键 | 图标 | 适用场景 |
|---|---|---|
| `mail` | 信封 | 邮箱 |
| `org` | 建筑 | 办公室 / 单位地址 |
| `phone` | 电话 | 联系电话 |
| `link` | 外链 | 个人博客 / GitHub / 主页 |
| `globe` | 地球 | 网站 / 国际页面 |
| `doc` | 文档 | 简历 PDF / 论文 |

填了不认识的值会自动回落到 `link`。

## 主题与视觉定制

所有颜色都由一个**色相值**(`--h`)派生,改一个数全站跟着变。

### 两个全局开关(在 `<html>` 标签上)

```html
<html data-mode="dark"  <!-- dark | light -->
      data-hue="212"    <!-- 0–359 -->
      data-alpha="1"    <!-- 0.1–1.0 -->
      data-cursor="1"   <!-- 1 | 0 -->
      data-cursor-size="26">
```

### 6 组预设配色

| 色相 | 名称 |
|---|---|
| 212 | 深海蓝 |
| 265 | 紫罗兰 |
| 158 | 翡翠绿 |
| 340 | 玫瑰红 |
| 28 | 琥珀橙 |
| 190 | 青碧 |

### 直接改 CSS 变量

`index.html` 里 `:root` 与 `html[data-mode="dark"]` / `html[data-mode="light"]` 三个块集中定义了全部设计令牌,常见可调项:

| 变量 | 作用 | 默认值 |
|---|---|---|
| `--radius` | 圆角半径 | `16px` |
| `--font` | 字体栈 | Inter / 系统字体 |
| `--glass-blur` | 毛玻璃模糊半径 | `22px` |
| `--glass-sat` | 背景饱和度提升 | `180%` |
| `--ease` | 全局缓动曲线 | `cubic-bezier(.2,.7,.3,1)` |
| `--h2` / `--h3` | 辅助色相(自动派生,可覆盖) | `h-24` / `h+53` |

## 常见问题

**Q:双击打开是空白页?**

脚本报错了。按 `F12` 看控制台。最常见的原因是文件编码不是 UTF-8,或复制时截断了内容。

**Q:改了 `content.json` 但首页没变?**

可能原因:
1. 用 `file://` 协议打开,浏览器拦截了本地文件请求 → 起个静态服务(见[快速开始](#快速开始))
2. 浏览器缓存了旧文件 → 强制刷新(`Ctrl+Shift+R`)
3. `content.json` 有语法错误 → JSON 不允许注释和尾逗号,用后台的「JSON 源码」面板校验一下

**Q:后台的修改怎么同步给别人?**

后台改动只存在你自己的浏览器里。要公开生效,请「导出 content.json」并提交到仓库。

**Q:为什么后台的口令不算安全?**

因为它存在 `localStorage`,而 `localStorage` 是客户端可控的。请把它当作「防止误触」而非「访问控制」。

**Q:数据会不会丢?**

`localStorage` 可能被浏览器清理(隐私模式、清缓存、存储配额回收)。**重要内容请及时导出备份**,并提交到仓库。

**Q:手机上鼠标特效很奇怪?**

触屏设备会自动关闭鼠标特效,这是设计如此(`@media (pointer:coarse)`)。

**Q:动画太多头晕?**

系统级开启「减弱动态效果」后,页面会自动停用大部分动画。

## 技术说明

实现上有几个刻意的取舍,记在这里免得后来者踩坑。

### 单文件优先

`index.html` 内含全部 HTML / CSS / JS,没有任何外部请求。代价是文件较大(约 160 KB),收益是:
- 双击就能用,不需要服务器
- 不会因为 CDN 挂掉而白屏
- 迁移时只拷一个文件

### 同步 XHR 而非 fetch

首页用 `XMLHttpRequest` 的**同步**模式读 `content.json`:

```js
const xhr = new XMLHttpRequest();
xhr.open('GET', 'content.json', false);   // false = 同步
xhr.send(null);
```

同步 XHR 早已被标为废弃,这里用它是为了拿到一个确定的时序:**数据就绪必须早于首次渲染**。否则页面会先渲染出厂默认内容,再跳变成真实内容 —— 肉眼可见的闪烁。

整个调用包在 `try/catch` 里,`file://` 下被 CORS 拦截时静默回落到内置默认,不产生控制台报错。

### 数组整体替换

深合并时数组不逐项合并,而是整体替换:

```js
out[k] = (isObj(base[k]) && isObj(over[k])) ? deepMerge(base[k], over[k]) : over[k];
```

如果逐项合并,删掉一条博客后旧数据会从底层「复活」。

### `undefined` 与 `null` 语义不同

- 键不存在或为 `undefined` → 保留底层的值
- 显式写 `null` → 清空

这样手写配置文件时,漏填的字段不会把默认值一起抹掉。

### 白名单校验(sanitize)

外部数据进合并前先过一遍白名单:只保留已知的顶层键,数组字段非数组则丢弃,数组元素中的非对象项过滤掉。否则渲染循环会在 `undefined` 上取属性,直接白屏。

### SVG 用 `createElementNS` 创建

不用「`innerHTML` 写字符串再取 `firstChild`」—— 那种写法依赖浏览器的 HTML 解析,图标表取到空串时 `firstChild` 为 `null`,`appendChild(null)` 会抛错。

### 首字按 Unicode 码点取

```js
const chars = Array.from(String(name));   // 不是 name.match(/[^\s]/)
```

正则会按 UTF-16 码元匹配,emoji 代理对会被劈成半个字符,渲染成乱码方块。

### 渲染幂等

每次渲染先清空容器再重建。所有自检用例都会连跑三次渲染,专门抓累积型 bug。

### localStorage 键清单

| 键 | 内容 |
|---|---|
| `site-content` | 站点内容(后台保存的完整对象) |
| `site-mode` | 当前模式 `dark` / `light` |
| `site-hue` | 当前色相 `0`–`359` |
| `site-alpha` | 当前透明度百分比 `10`–`100` |
| `site-cursor` | 鼠标特效开关 `1` / `0` |
| `site-cursor-size` | 光标尺寸 `16`–`48` |
| `admin-pass` | 后台口令(仅后台使用) |

### 浏览器支持

需要 `backdrop-filter`(Chrome 76+ / Safari 9+ / Firefox 103+)、CSS 自定义属性、`IntersectionObserver`。

不支持 `backdrop-filter` 时会自动退化为较实的背景色(`@supports not` 兜底)。
